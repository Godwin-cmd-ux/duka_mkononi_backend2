WHAT WAS BUILT
--------------
A read-only AI capability that reviews your business's products and tells you
which ones are LOSING money, have THIN margins, or are missing prices — with a
suggested selling price computed in trusted PHP (never guessed by the AI).

Endpoint:  POST /api/ai/price/suggest     (requires a logged-in seller/admin)

All money math happens in trusted code. Gemini only explains and prioritises,
and its output is sanitised so it can never invent a product, a price, or a
number.

STEP 0 — PREREQUISITES
----------------------
1. GEMINI_API_KEY must be set in .env   (it already is).
2. Start the API:      php artisan serve
   Base URL used below: http://127.0.0.1:8000
3. You need at least ONE active product that belongs to your business, ideally:
     - one product where selling price < buying price   (LOSS)
     - one product with a thin margin                   (THIN)
     - one product with no buying price                 (MISSING_COST)
   If you don't have these, you can still run the test and just check the shape.


STEP 1 — GET A TOKEN (log in)
-----------------------------
Replace the email/password with a real seller or admin account.

curl -s -X POST http://127.0.0.1:8000/api/login \
  -H "Content-Type: application/json" \
  -d '{"email":"SELLER_EMAIL","password":"SELLER_PASSWORD","role":"seller"}'

Expected: a JSON body containing  "message":"Login successful",  "token":"...".
Copy the token. In every command below, paste it after "Bearer ".

(WINDOWS USERS: if the single-quoted JSON is awkward in cmd.exe, run these in
 Git Bash, which the project already uses.)


STEP 2 — HAPPY PATH
-------------------
curl -s -X POST http://127.0.0.1:8000/api/ai/price/suggest \
  -H "Authorization: Bearer PASTE_TOKEN_HERE" \

  -d '{}'

        "priority_score": <number>,

      },
      ... sorted with the most urgent (LOSS) first ...
    ],
    "insights": [ { "product_id": "...", "severity": "high|medium|low",
                    "title": "...", "action": "..." } ],
    "watchouts": [ "..." ],
    "limitations": [ "...", "...", "..." ],
    "ai": { "available": true, "degraded": false, "code": null,

 TEST FLOW — CAPABILITY #5: BUSINESS HEALTH SCORE & WEEKLY COACHING
 Duka Mkononi  (Gemini-Powered Expert System)
==============================================================================

WHAT WAS BUILT
--------------
A weekly, explainable business health digest. Four documented components —
margin, stock cover, sales trend and expense ratio — are scored 0–100 in
trusted PHP, weighted, and combined into one band. If there is not enough
evidence the app produces NO score at all (never a misleading one). Each digest
also lists meaningful changes vs. the previous week and up to three evidence-
based suggested actions, and is stored once per business + week so authorized
users can review the history.

Endpoints (all require a logged-in seller/admin)
  POST /api/ai/reports/weekly          generate / refresh a digest
  GET  /api/ai/reports/weekly          latest stored digest
  GET  /api/ai/reports/weekly/history  stored digest summaries
  POST /api/ai/health/setup            admin: create the storage table

Scheduled job
  php artisan ai:weekly-digests        (runs weekly per ai.health.delivery)

Files added/changed
  config/ai.php                                    <- health weights/thresholds/delivery
  app/Models/AiWeeklyDigest.php
  app/Services/Ai/HealthNarrator.php               <- 8-locale digest text
  app/Services/Ai/BusinessHealthScore.php          <- the score engine
  app/Services/Ai/HealthDigestService.php          <- retrieve + store (idempotent)
  app/Http/Controllers/Api/AiHealthController.php
  app/Console/Commands/GenerateWeeklyHealthDigests.php
  routes/api.php, routes/console.php
  tests/Unit/BusinessHealthScoreTest.php, tests/Feature/AiHealthRouteTest.php

FRONTEND (seller app + website, in all 8 languages)

The digest history lives in a Supabase table. Create it with an admin call to
POST /api/ai/health/setup, or paste this SQL in the Supabase SQL Editor:

  CREATE TABLE IF NOT EXISTS ai_weekly_digests (
      id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
      business_id UUID NOT NULL REFERENCES businesses(id) ON DELETE CASCADE,
      period_start DATE NOT NULL,
      period_end DATE NOT NULL,
      locale TEXT NOT NULL DEFAULT 'sw',
      score NUMERIC,
      band TEXT,
      sufficient BOOLEAN NOT NULL DEFAULT FALSE,
      coverage NUMERIC NOT NULL DEFAULT 0,
      headline TEXT,
      digest JSONB NOT NULL DEFAULT '{}'::jsonb,
      created_at TIMESTAMPTZ DEFAULT NOW(),
      updated_at TIMESTAMPTZ DEFAULT NOW(),
      UNIQUE (business_id, period_start, period_end)
  );
  CREATE INDEX IF NOT EXISTS idx_ai_weekly_digests_business
      ON ai_weekly_digests (business_id, period_start DESC);

STEP 2 — GENERATE THE WEEKLY DIGEST
-----------------------------------
curl -s -X POST http://127.0.0.1:8000/api/ai/reports/weekly \
  -H "Authorization: Bearer $TOKEN" -H "Content-Type: application/json" \
  -d '{"locale":"sw"}'
