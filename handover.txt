4. THE RULES OF THIS TASK (from instruction3.txt — non-negotiable)
--------------------------------------------------------------------------------
Section 2 — working rules:
  2.1 Inspect before editing. Inventory routes, controllers, middleware,
      services, Supabase schema/RLS, the existing Gemini integration (Laravel
      + legacy Node `ai/`), Expo nav/API client/language context, all relevant
      Blade pages, tests and config. Don't duplicate features that already
      exist in another file.
  2.2 One authoritative backend: Laravel owns the APIs/business logic. Do NOT
      add a second conflicting implementation to the legacy Node/Express
      server. Preserve WebSocket presence + email functionality.
  2.3 Production data safety: reversible migrations where possible, no
      destructive schema changes, never reset the live DB, never modify
      production records to make tests pass, don't change product IDs /
      business identities / order statuses / payment flows / roles without a
      verified requirement.
  2.4 No fake functionality: real integrations or an honest report of the
      missing prerequisite. No sample arrays, no hardcoded AI answers, no
      buttons that do nothing, no TODO placeholders.
  2.5 Maintain the existing app: keep routes/response formats compatible,
      keep language switching, auth, role dashboards and existing AI imports
      working; use feature flags for rollout/rollback.

Section 3 — shared AI architecture (already largely built; extend it):
  3.1 One Gemini adapter: model selection per capability, timeouts, bounded
      retries w/ exponential backoff + jitter, 429/503 handling, size limits,
      structured JSON validated before use, correlation IDs, safe logging.
      API keys server-side ONLY — never in JS, Expo, Blade, API responses.
      Config in `config/ai.php` (env-driven).
  3.2 Allow-listed, server-executed tools only. The model may REQUEST a tool
      call; only trusted PHP executes it. Never let Gemini run SQL, touch the
      DB directly, or pick another tenant's ID. Every tool enforces auth,
      business ownership, date-range and result limits.
  3.3 Explicit contracts per capability: input validation, output schema,
      error contract, permissions. Validate model output before returning or
      mutating anything; bounded repair attempts; never silently promote AI
      output to business data.
  3.4 Grounding: financial/inventory math happens in trusted code or
      PostgreSQL, never the model; missing info reported as missing; show date
      ranges/sources/limitations; never invent records; treat DB/docs/reviews/
      prompts as untrusted input; never leak another business's data through
      prompts, logs, caches or history.
  3.5 Human confirmation + idempotency for consequential actions:
      Retrieve -> Propose -> Validate -> Preview -> Confirm -> Authorize ->
      Commit -> Audit. Server-generated single-use tokens / payload-hash
      binding; repeats must not duplicate transactions. Read-only answers
      should NOT require confirmation.
  3.6 Audit everything (AI_* audit actions): request id, capability, user,
      business, status, duration, retries, validation failures, whether a
      human confirmed/edited/rejected. Never log keys, passwords, OTPs,
      payment credentials or unnecessary personal data.

Section 12/14: vertical slice per capability, test before moving on, staged
rollout via feature flags, and NEVER claim a test passed / migration applied /
integration connected unless it actually did.

Additional repo conventions this session followed (keep them):
  * Tests: `tests/Unit/*Test.php` = pure-function contract tests (no DB/HTTP/
    Laravel helpers where possible); `tests/Feature/<Name>RouteTest.php` =
    route registered + `auth.jwt` middleware assertion.
  * Locales: every server-side/UI string exists in all 8 languages, in BOTH
    `Duka_mkononi/locales/{lang}.json` and root `locales.json` (same key
    sets). The app's `t(key, params)` supports `{param}` substitution
    (`context/LanguageContext.tsx`).
  * Expo calls: `API_BASE_URL` from `constants/api`, `AsyncStorage
    .getItem('userToken')` for the bearer token, shared
    `lib/network.fetchWithTimeout(url, opts, ms)` (retries the alternate API
    host), `'ngrok-skip-browser-warning': 'true'` header on POSTs, `useLang()`
    for translations, `t('section.key')`.
  * Blade surfaces get their strings through the `tc('key')`/`content_review.`
    prefix helpers from the DM locale widget partial
    (`partials/dm-lang-widget.blade.php`, `partials/dm-locale.blade.php`).
  * Amounts/scales: format money in trusted code; keep TZS integer amounts.
  * The response style of AI endpoints: `{'success': true, 'capability': ...,
    ...}` payloads and `$this->json()/error()` with `code` strings
    (e.g. FORBIDDEN_ROLE, FEATURE_DISABLED, INVALID_INPUT).

5. GOTCHAS ALREADY HIT (do not repeat)
--------------------------------------------------------------------------------
* Decision/API enums must match EXACTLY across layers: capability #16's
  decision endpoint accepts `approve|reject|request_edit` — all four UI
  surfaces initially sent `edit` and would have 422'd. After any endpoint
  change, grep every surface (2 blades + 2 Expo screens) for the payload.
* PHP array keys: `'1'` silently coerces to int `1` — when indexing by
  string ids/keys, cast carefully (this bit an earlier capability too).
* `rtrim($str, '0')` ate the significant zero of "20" — use exact-match
  sanitising, not character-class trims, on user/model text.
* Check the mount point you think you edited actually exists: `muuzaji/
  tangaza.tsx` (Expo) is the Ad Copy Studio, NOT a "my ads" list — verify
  structure with grep before inserting JSX.
* `tsc` tuple casts: `as [['a'|'b', string]]` is a 1-TUPLE, not an array —
  use `as [string, string][]` and narrow at use sites.
* Locale parity must be checked in BOTH `Duka_mkononi/locales/*.json` AND
  root `locales.json` — they are separate catalogs and drift silently.

6. CLOUD ENVIRONMENT LIMITATIONS (Freebuff workspace) — IMPORTANT
--------------------------------------------------------------------------------
* TERMINAL: synchronous only, hard timeout (default 30s, max 180s). No
  background processes (`&`, `nohup`), no long-running servers. Commands run
  from the project root; chain with `&&`/`;` but keep jobs bounded.
* DEV SERVERS: NEVER start them yourself (`php artisan serve`, `npm run dev`,
  `vite`, ...). Freebuff owns preview lifecycle via the separate
  `freebuff-preview` command (set-install / set / set-build, `start`,
  `restart`, `status`, `logs`) — run it as its own command, never chained.
  This project's preview wiring (Laravel + Expo) may not be configured; if
  `freebuff-preview status` shows nothing, don't improvise — say so.
* FILE EDITS: use the file tools (`write_file`, `str_replace`), never `sed`,
  shell redirection or ad-hoc scripts to modify source — those can fail to
  persist through the synced build state. Terminal is for inspection, installs
  and checks only.
* ENV FILES: do not edit `.env` / `.env.local`, do not read or print them or
  any secret. `freebuff-env list` shows key NAMES only. Missing secrets ->
  name the required env-var keys and ask the user to add them in
  Settings/Environment. Gemini key: config via `config/ai.php` env names only
  (e.g. whatever `AI_*` vars it reads) — document names, never values.
* `code_search` (ripgrep tool) was UNRELIABLE in this workspace — it returned
  unrelated file dumps (locales.json/package-lock) regardless of pattern/cwd.
  Use `grep -n`/`rg` through `run_terminal_command`, or `read_files` with
  offsets, instead. Re-test it before trusting results.
* NO BROWSER/DEVICE VERIFICATION available here: the Blade flows need a
  running Laravel + live Supabase + a logged-in staff account, and the Expo
  screens need a device/emulator. Verification was therefore: phpunit,
  `php -l`, tsc, extracted-`<script>` `node --check`, locale-parity scripts,
  and line-by-line API contract review. A visual pass remains outstanding —
  list it under "manual verification steps" in the final report.
* PHP IS AVAILABLE (`php`, `php vendor/bin/phpunit` works; live Supabase is
  reachable from tests — the suite runs against it, so treat DB writes in
  tests carefully and clean up scratch rows like earlier sessions did).
  Node 22 is available. `Duka_mkononi/node_modules` is installed
  (npm-style); run tsc as `node_modules/.bin/tsc --noEmit` from that folder.
  A scratch `.php-lint.js` (bracket-balance linter from a session that
  thought PHP was missing) sits at the repo root — disposable, may be deleted
  or just committed as-is.
* HOSTED TERMINAL/GIT: this is a Freebuff Cloud GitHub-connected repo.
  Credentials are injected per-command; never ask the user for a PAT/SSH and
  never rewrite the remote. Commits/pushes are normally owned by Freebuff's
  Changes panel — only run git delivery commands when the user explicitly
  asks (as they did for this handover). Stage only task-related files; never
  `git reset --clean`/history rewrites.
* Platform checks: the "Freebuff Vite/Convex" template rules do NOT apply to
  this Laravel+Expo repo (no Convex, no `bun tsc -b`). The checks that matter
  here are phpunit + `Duka_mkononi` tsc + locale parity.
* `.locale-check.js` referenced in older notes does NOT exist and was never
